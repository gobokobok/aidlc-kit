# Technical plan: Guest request triage

Plan for handoff HND-001. The prompt, the golden set and the thresholds are
fixed by the package; this plan says how to build the service around them.

## Components
- **Message intake** receives a guest message from the guest app and passes
  the text on. Delivers REQ-001.
- **Triage service** renders the approved prompt (ASSET-001 v1) with the
  message, calls the model, and checks the answer is one JSON object with a
  valid `category` and a boolean `urgent`. Delivers REQ-001 and REQ-002.
- **Staff console** shows each message with the suggested queue and urgent
  flag, urgent ones first. Staff confirm or change both. Delivers REQ-002 and
  REQ-003.
- **Decision log** records what the model suggested and what staff chose.

## Interfaces and contracts
- Intake to triage: `{message_id, text}`.
- Triage to console: `{message_id, category, urgent, needs_manual_sorting}`.
  `category` is one of `housekeeping`, `maintenance`, `food_and_beverage`,
  `front_desk`, `other`.
- A model answer that does not match the contract is never shown as a
  suggestion; the message is shown with `needs_manual_sorting: true`.

## Data
- Guest message text may contain names and room numbers (Tier 2: personal
  data). It goes to the model provider and the decision log, nowhere else.
- The decision log keeps message ID, suggestion and staff choice for 90 days;
  message text is kept only as long as the guest app keeps the conversation.
- The model provider must not train on the messages (contract term to confirm
  with the data owner before launch).

## Risks
- A missed urgent message. Mitigation: AC-002 in CI, and staff see every
  message, so a missed flag still reaches a person.
- Staff trust the suggestion without looking. Mitigation: the console shows
  the message beside the suggestion, and the decision log lets Ops review
  how often staff change it.
- The provider is unavailable. Mitigation: messages fall back to
  `needs_manual_sorting`; nothing blocks.

## Regression gate
The golden set in the handoff package (`golden.yaml`, 20 cases) is the
regression gate for the implementation: the same cases must keep passing the
criteria thresholds, and the check runs in CI.

## Tasks
```yaml
- id: T-001
  title: Triage service renders ASSET-001 v1, calls the model and validates the answer
  criteria: [AC-001]
- id: T-002
  title: Fall back to needs_manual_sorting when an answer does not match the contract
  criteria: [AC-001]
- id: T-003
  title: Staff console shows suggestion and urgent flag, urgent messages first
  criteria: [AC-002]
- id: T-004
  title: Staff confirm or change the suggestion; record both in the decision log
  criteria: [AC-001]
- id: T-005
  title: Run the golden set in CI as the regression gate
  criteria: [AC-001, AC-002]
```
